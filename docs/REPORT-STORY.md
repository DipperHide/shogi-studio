# 报告摘要与关键时刻（0.19）

报告顶部由简单的准确率文字和最大损失三手，改为走势摘要与可展开的关键时刻卡片。默认展示一条，可展开最多十条；每条有原版分类图标、着手、前后真实评分、双色小评分条和变化说明。点击卡片定位报告曲线与该手明细，随后可查看棋盘、预览线路或从这里继续下。说明弹窗返回后保留选中着手和展开状态。

## 静态参考

来源仍为用户给出的 Chessis 20.9 APK，原文件未修改。

- `res/layout/dialog_game_report.xml`：顶部 `llGameStorySummary`、摘要、可点击关键时刻说明、卡片列表及展开按钮。
- `p328r2/C4570h.java` 的 `m9423I`：默认一条、展开最多十条；18 dp 分类图标、13 sp 单行着手、前后评分、12.5 sp 原因、点击跳转。`m9421C` 的双色标记采用 ±500 归一化评分的线性比例，非詰み限制在 8%–92%。它只是紧凑的评分示意，不是胜率。
- `ViewOnClickListenerC4568f.java`：展开／收起和关键时刻说明；该操作不离开报告。
- `p197a2/AbstractC1742p.java` 的 `m2741i`、`m2727S`、`m2743k`、`m2744l`：候选转折、重点选择和排序；`m2750r`、`m2718J` 给出优势转换与詰み原因；`m2742j` 统计双方机会和波动；`m2757y` 逐一检查后续局面是否回到均势。
- `m2735c` 包含复杂的最终摘要和补充转折。本版接入有依据的主要模式，尚未逐一移植该方法所有分支、阶段表现评语和补充着手规则。
- Java 反编译的候选条件有倒置。实际候选筛选以原始 `La2/p;.i` DEX 为准，指令证据在 `.work/chessis-reference/dex-evidence/a2-p-i.txt`；另保存 `q/r/k/l/y`。例如 00ba–00c6 是两侧明确优势相互反转，00cc–00da 是错失勝机且原有优势至少 300、之后至多 100，00f3–0103 是均势转为明确优势。

## 模型与证据

`shogi_report_story.gd` 的当前模型名为 `shogi-story-19-reference-adapted`。沿用分类中的 `2.209248` 将棋评分单位转换，再取整；显示分数仍用原生将棋分，所有评分均以先手为正向。詰み采用有符号距离哨兵。终局沿已有将棋阶段判断，不使用国际象棋的盘上子力残局标准。

候选依据分类及局面变化，包含明显优势反转、错失胜机、胜势流失、均势被打破、妙手和重要优势降级。本来已明显落败、只是进一步变差的普通波动会被排除。按实际终局获胜方优先寻找对手的关键失误，其余按事件权重、变化幅度和手数排序，去重并限制十条。原版特别补充转折和失误集中时的重选逻辑尚未完整迁移。

摘要区分走势平稳、双方均有机会、逆转、关键失误后保持优势、完整和棋、棋盘评价与超时／实际结果不一致等情况。`closed` 必须同时满足分析完整、战术复核完成和棋谱已有结果；部分报告不使用后续已知胜者，也不会把尚未结束的棋谱当作和棋。无候选不生成虚构关键时刻。分析过程中摘要随已完成局面更新。

模型导出包含已分析手数、完整性、实际结果适用状态、走势统计，以及每条卡片的原始前后引擎数据、分类、优先级和原因。当前属于原版主要摘要模式的将棋迁移，尚不是完整故事引擎的等价实现；完整复制目标仍保留在 `CHESSIS-PARITY.md`。

## 绘制修复与验证

实际 140 手历史对局在多尺寸切换时，暴露原评分曲线过零处极窄三角形被多边形剖分器拒绝的问题。每段面积原本就是凸三角形或梯形，现用直接三角形绘制，保留原面积和颜色，避免近零面积产生剖分错误。

- `story15_test.gd`：原 DEX 条件边界、詰み、均势、候选排序、前缀隔离、未结束棋谱、超时结果和十条去重上限。评分分支使用明确的合成测试数据，不当作真实棋力分析。
- `chessis15_test.gd`：重新用真实 YaneuraOu 分析完整历史棋谱，停止／续跑、原始输入保留、完整胜者、卡片评分与实际 samples 对应、四种尺寸与两种主题、展开／收起、触控定位、说明返回和原局隔离。
- 实际 Windows 成品另外验证摘要、卡片、说明页与已有引擎／练习流程。证据与发布记录见 `review/app/chessis15/REPORT.md`。

原版仍缺可运行分包，界面对照以本地静态资源和控制代码为依据。真实支付、Android 真机及其他未完成项目的状态未因本轮改变。

## 0.19：阶段表现、持续优势与结果状态

新增 `shogi_report_phase_story.gd`。不是把长篇评语加回阶段统计弹窗，而是在报告顶部、没有选中关键时刻可概括时，按原版 `a2/p.c` 的 `0356..06e4` 分支生成摘要：

- 持续早期优势：获胜方第一次达到归一化 +200 不晚于已分析局面数量的一半，此后最低评价严格高于 -100。根据对手的细小不精确、单次失误、多次失误、单次漏着或反复错失机会选择不同文字。
- 阶段表现：只比较双方都有可计分着手的阶段。阶段准确率相差至少 5.0 时记一方表现更好；最大差距相同时保留较早阶段。若获胜方至少两个阶段较好、对方没有较好阶段，使用持续优于对手的摘要。否则指出具体阶段。双方整局准确率至少 85 才使用“整体发挥稳健”的分支。
- 结果未知时，只概括某方阶段表现；确认和棋时说明另一方守住均势。稳定获胜的兜底摘要也按错误概况区分，不凭空制造关键时刻。
- “相关失误”只统计行棋前本方归一化评分严格大于 -200 的失误／漏着／错失胜机。单次失误的阶段用所有阶段计数核对，分布在多个阶段时不声称发生于某一阶段。

原始助手方法 `I`、`N`、`p` 和 `j` 的指令已保存到 `.work/chessis-reference/dex-evidence/`。`verify_story19_dex.py` 是只支持必要操作码的离线解释器，直接读取这些指令，核对选中的原版文案资源、上下文计数和实际 140 手棋谱输入；遇到不支持的指令会失败。它不运行完整 Android APK，也不代替原版动态 UI 验收。

一项明确的数值适配：本项目准确率只存一位小数，阶段差距按显示值的整数十分位比较。这样 8.2 与 3.2 的差距会按 5.0 处理，避免二进制小数误差使边界漏判；不将这个修正声称为对原版浮点偶然误差的逐位复制。

结果判断优先于阶段叙述。确认结束而最终评分在 ±100 内时，区分超时、认输与其他结果；未结束或分析尚未完整时，±300 的胜势只描述最新已分析局面，不借用完整棋谱的未来胜者。部分报告的阶段计数、最低后续评价和评分也只使用已完成前缀。

界面继续按 `dialog_game_report.xml` 与 `C4570h.m9423I` 调整：故事面板上下 12、左右 14；正文行距 3；关键时刻卡片加入固定 12×12 的先后手颜色标记，着手文字加粗、说明左缩进 24；展开按钮居中。真实历史在四尺寸、两主题下检查，合成分支另覆盖 360×760 与 852×393。合成场景仅用于验证分支，截图标明“非引擎测量”，不作为真实棋力结果。
