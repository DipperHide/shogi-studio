# Android 实机基线（进行中）

2026-09-11，用户连接手机后，安装并启动了与 GitHub Release 哈希一致的 0.33.0 ARM64 APK（versionCode 51）。设备报告 V2203A、Android 14／API 34、SM8250／Adreno 650、1080×2400、480 dpi。本页是阶段性实测，不代表全功能或双机验收。

已确认启动、棋盘显示、本地引擎评分、触摸打开菜单、近期 26 局目录、195 局离线目录以及载入完整 140 手棋谱。用户亲自确认左下角菜单可用；ADB 在该边缘的点击未稳定触发，中心区域点击可用，暂不据此认定应用触摸故障。

| 场景 | 采样 | 帧间隔中位数 | P95 | 最大值 |
|---|---:|---:|---:|---:|
| 二维棋盘静止 | 127 帧／约 2.1 秒 | 16.71 ms | 16.75 ms | 16.87 ms |
| 从离线库载入 140 手棋谱 | 353 帧／约 6 秒 | 16.71 ms | 16.78 ms | 133.66 ms |

第二个场景有两次超过 50 ms 的帧间隔。数据来自应用 SurfaceView 的 SurfaceFlinger 实际呈现时间；Android View 的 `gfxinfo` 不代表 Godot 游戏帧，因此未用它宣称游戏帧率。短采样不足以推断长时间、3D、发热或电池表现。

第一次冷启动 Activity 的 `TotalTime` 为 419 ms，但 Godot 主循环稍后才启动，不能将 419 ms 当作首张棋盘时间。首次空闲内存读取：PSS 407,454 KiB（约 398 MiB）、RSS 512,340 KiB；需要继续区分引擎、NNUE、字体、纹理及棋谱数据。

下一步验证回放与连续点击、3D、文件导入、前后台恢复和保存选择。性能方向优先检查载入时主线程工作、启动预加载、无变化时的重复界面计算和静止重绘；先记录同一设备、相同场景的基线，再比较改动。交互方向优先处理纯回放不保存、修改后保存／不保存选择、导入用途选择及更明亮的龙王图标背景。

原始截图、日志与帧时间位于本机 `review/app/chessis33/android-device/`。设备序列号和其他应用数据未放入公开报告。

## 0.34 启动菜单修复

2026-09-11 在同一 Android 14 设备上复现了冷启动后底部菜单和更多按钮不响应。触摸坐标正常；首次文字排版暂时增大分析区域，随后透明的滚动区域仍挡住底部按钮。落子会触发重新布局，因此表现为必须先走一步。现在分析区域的最小尺寸变化后会自动重新布局。

最终 0.34.0 APK（versionCode 52）验证范围：恢复已有对局后，不新增着手即可打开菜单和更多；点击右侧遮罩关闭菜单，棋盘保持原局面。菜单内部点击不会关闭，保存确认框仍要求明确选择。桌面回归额外覆盖全新零着手对局、横竖屏、2D／3D 及取消触摸。

本次为上述交互的专项验证；此前的帧时间数据仍属于 0.33，不能据此宣称 0.34 帧率改善或全功能已完成实机验收。最终 APK 校验值、验证范围与截图摘要见 [0.34 验证记录](releases/v0.34.0-validation.json)。原始证据保留在本机 `review/app/chessis34/android-device/`。
