# 阶段准确率弹窗的参考与将棋适配

0.18 继续根据用户提供的 Chessis 20.9 APK 静态布局与控制代码迁移阶段弹窗。原 APK 缺少运行分包，没有声称经过原版动态逐屏对照。

## 原始依据

- `.work/chessis-reference/res/layout/dialog_phase_accuracy.xml`：木纹背景，18 sp 标题，玩家图标、15 sp 单行粗体姓名，13 sp 整局准确率胶囊，右上角关闭。
- `.work/chessis-reference/java/sources/p328r2/C4573k.java`：宽度为屏幕的 92%，最大 440 dp；卡片按开局、中局、终局排列，标题包含本方在该阶段的手数。阶段评分使用彩色填充和黑／白对比文字。
- `C4573k.java` 的卡片构建及 `m9436j0`：只列出非零的错失胜机、漏着、失误、不精确，依次排列；16 dp 图标配 13 sp 数字，黑色半透明胶囊。阶段已计分且没有这些错误时显示绿色勾号和“没有失误”。
- `.work/chessis-reference/res/drawable/bg_phase_card.xml`：黑色透明度 `0x59`，白边透明度 `0x38`，8 dp 圆角，10 dp 内边距。卡片间隔 8 dp。
- `.work/chessis-reference/java/sources/p197a2/AbstractC1742p.java` 的 `m2738f`、`m2740h`：只统计已分析范围；某方在阶段内没有着手时不生成卡片。阶段准确率不叠加整局的额外错误惩罚。
- 绿色勾号来自原 `ic_circle_check.xml`，通过既有转换器转为 SVG，保留来源和散列于 `godot/assets/reference-ui/provenance.json`。

## 实现

`shogi_phase_accuracy_view.gd` 单独生成阶段模型和紧凑视图。0.12 原先添加的长篇说明、全类别零计数行、阶段区间、划分原因及阶段复盘按钮已从该弹窗移除；这些不属于原版阶段卡片。报告图表、着手详情和继续对弈入口继续负责定位与续下。关闭阶段弹窗保留报告的选中手数。

将棋用先手／后手棋子标志替换国际象棋兵图标。每阶段只显示本方手数，例如完整 140 手棋谱，先后手分别统计各自的 70 手。持驹和 9×9 布局需要额外空间；本页不改变棋盘。

只有真实匹配定式库的全定式阶段显示“定式”。唯一合法着的权重为零，没有可计分着手时显示“—”；本方尚无已分析着手时显示空态。不把这两种情形视为满分或“没有失误”。阶段划分仍采用将棋的交战／王周围攻势启发式，不套用国际象棋子力残局阈值。

本轮验证见 `review/app/chessis18/REPORT.md`：实际引擎分析完整历史棋谱、部分报告续跑、双方、四尺寸和两主题，另有真实定式与唯一合法着局面的边界验证。Python 从实际逐手数据独立重算阶段手数、错误数量及聚合分数。

## 尚存差距

原版复杂走势摘要中的阶段表现分支（`game_story_phase_*`）与这个只读统计弹窗是两项不同功能。此次没有补齐全部故事分支、估计 Elo 或校准将棋棋力；也没有完成原版动态像素对照、真实支付或 Android 真机验收。
