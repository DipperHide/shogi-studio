# 准确率详情（0.17）

原版把阶段条、整局准确率和 ACPL 分为不同点击入口。0.16 将准确率合并进阶段统计，缺少逐手表现图；0.17 接入独立准确率详情，同时把阶段详情改成参考的居中木纹弹窗。

## 静态参考证据

- `phase_ribbon.xml`、`C4570h.m9432z`、`ViewOnClickListenerC4569g`：准确率和 ACPL 是独立标签，准确率打开 `C4565c`，阶段评分另有入口。
- `dialog_accuracy_insight.xml` 与 `C4565c`：玩家、30 号整局数值、简短解释、144 高横向图表、点击后出现的着手卡片。窗口宽度为屏宽 92%，最大 440；木纹背景裁切圆角。阶段窗口 `C4573k.mo85J` 使用相同宽度上限。
- `AccuracyDeviationChartView`：0／50／100% 刻度；整局准确率虚线；每手间隔 13、线宽 5、端点半径 3、选中高亮线宽 9。手势超过滑动阈值不当成点选；图点点击显示原手数、分类、单手准确率、前后评价与局势。
- `a2/p.d`（反编译为 `AbstractC1742p.m2736d`）与 `C1727a`：逐次剔除一手，用不含分类罚分的聚合计算差值。按提升量降序、单手准确率升序、原手数升序选默认高亮，提升不足 0.5 不高亮。该字段只用于图中初始高亮，参考控制代码没有显示布局中默认隐藏的“最大下降”附加卡片。
- 点击详情卡片经 `accuracy_insight_move_request` 关闭两个报告窗口并定位原棋谱。将棋版通过同一报告棋盘入口实现，同时显示对应保存的候选线路。
- 字符串及资源保存在 `.work/chessis-reference/string-resources.xml`、原布局与 Java 目录中；原 APK 未修改，也未动态运行。

## 将棋对应行为

阶段评分条继续打开阶段统计；“准确率”打开独立每手表现；开启 ACPL 后，它有单独的说明入口。详情页关闭时保留报告选中手。点击图点只选中详情卡片；点击卡片进入对应棋盘，可以继续逐手回放、预览候选或从该处开始下。

图点保持原将棋手数，不换算为国际象棋回合编号。先后手依据实际局面行棋方，支持后手先行的 SFEN 起点。只收录本方已分析、参与评分的着手：排除定式和唯一合法着。未分析的后续着手不会生成占位点；没有可计分着手时显示 `—` 和空态说明。

整局数值与主报告使用同一个聚合结果，点的数值直接使用该手 `metrics.accuracy`。前后评分均保留引擎原始将棋单位，以先手为正，詰み显示距离。局势文字根据参考详情页的 50／250／600 阈值，在项目已有将棋评分尺度换算后判定；这与选中着手卡片的局势阈值不同，原版也使用不同阈值。

分类为不精确／失误／漏着／错失胜机而单手准确率饱和到 100 时，文字显示“局面已定”的不适用状态；图点仍保留原始数值。没有把已定局面的坏棋描述成完美着手。

打开的详情固定使用该次分析快照，返回报告后读取最新进度。长图支持横向触摸拖动及桌面拖动，滑动不改变选中手；键盘左右键切换，Home／End 跳到首尾并滚动显示对应点。

## 验证与限制

- `accuracy17_test.gd`：数据筛选、原手数、快照隔离、局势边界、詰み、饱和准确率、默认高亮排序。
- `chessis17_test.gd`：本轮重新分析完整 140 手历史棋谱、部分报告与续跑、双方／明暗／四种尺寸、真实触控滚动和定位、键盘首尾、空态、独立阶段和 ACPL 入口、原局隔离。
- `accuracy17_gote_test.gd`：实际引擎分析后手先行 SFEN，确认图点保持第 1 手后手、第 2 手先手及正确前后评分。
- `verify_accuracy17.py`：Python 独立重算整局与剔除一手的聚合，对照每个实际图点的原手数、分类、评分和前后局面。
- 实际 Windows 成品另测准确率详情、图点卡片、棋盘定位及阶段／ACPL 入口；APK 核验相应脚本、资源、签名与版本。证据见 `review/app/chessis17/REPORT.md`。

0.18 已将阶段统计调整为原版对应的紧凑只读卡片，见 [PHASE-ACCURACY.md](PHASE-ACCURACY.md)。走势摘要中的完整阶段表现分支、估计 Elo、连续将军循环等复杂权重仍未完整迁移。将棋缺少校准的等级分映射，因此没有套用原版国际象棋的专家／初学者准确率基准。完整差距见 [CHESSIS-PARITY.md](CHESSIS-PARITY.md)。仍没有 Android 真机及可运行原版的逐屏对照。
