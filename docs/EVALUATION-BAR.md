# 局面评价条

0.26 将原来棋盘边缘的细线改成带九个刻度、评分和搜索深度的评价条。实时分析和报告回放共用同一显示，旧报告没有候选缓存时也能读取评分、深度和实际詰手数。

在「设置 → 棋盘与棋子 → 评价条位置」选择：

- **智能**：普通对弈放在底部；报告回放空间不足时移到左侧，同一报告、同一方向内不会来回跳动。
- **左侧**：固定显示在棋盘左边，暂停分析和引擎选项移到旁边。
- **底部**：在分析区顶部显示完整评分和深度。
- **仅报告回放时在左侧**：其余场景使用底部。

左侧条下端显示 `dN` 深度；评分仍可从候选行查看，聚焦评价条还可读取完整无障碍说明。原局暂停与恢复、从此局面续下、候选数量调整继续可用。关闭评价条后显示引擎状态。

正分表示先手优势，负分表示后手优势。横条的先手浅色区域固定在左；竖条的浅色区域位于先手所在方向，随棋盘翻转改变起点。`+詰7` 表示搜索发现先手七手内可詰，`−詰7` 表示后手。未知局面显示「—」和中线；只在终局对应的最后一手显示实际结果，不把最终胜负借给此前的回放局面。

评价条使用线性评分刻度：`clamp(0.5 + 先手评分 / 2.209248 / 1000, 0, 1)`。2.209248 是本项目报告中既有的将棋尺度转换；文字仍显示原始引擎分数除以 100。旁边的胜率估计继续用独立的 sigmoid 换算，两者含义不同。评价条从当前可见进度用 750 毫秒过渡至新值，中途更新接续当前画面；关闭动画时立即更新。

## 参考依据与适配

本地静态证据来自用户提供的 Chessis 20.9 APK，哈希见 `godot/assets/reference-ui/provenance.json`。没有运行原版进行逐像素比对。

| 证据 | 对应实现 |
|---|---|
| `res/layout/activity_main.xml` 的 `pbScore`、九个刻度、`tvScore`、`flSideEvaluationBar` | 24 像素横条、中央粗刻度、分数／深度、左侧位置 |
| `res/drawable/score_progressbar_bg.xml` | 深色 `#483D41`、浅色 `#E7DFDE` |
| `C3369A0.m7286i0`、`RunnableC0870a` case 6、`C4128t.applyTransformation` | 线性评分、从现有进度继续、750 毫秒动画 |
| `MainActivity.m4490L0`、`m4559m`、`m4539e2` | 翻转竖条、移动引擎按钮、侧边 `dN` |
| `MainActivity.m4531c0`、`preference_main_settings.xml` | 四种位置策略、智能模式一次切换 |

智能判断使用将棋的 9×9 棋盘和两个持驹区的空间预算，并非照搬国际象棋的 8×8 高度公式。关卡练习、联机及候选预览隐藏当前评价，避免显示其他局面的分数。局面编辑器仍未接入独立实时评价。终局文案、詰记号和先后手标记为将棋适配。

验证命令：`./scripts/test_chessis26.ps1`；评分及设置测试：`godot --headless --path godot --script res://tests/evaluation26_test.gd`。结果见 [0.26 测试](TESTING-0.26.md)。
