# 0.36.1 本地测试版：只看己方线路，电脑保持所选难度

版本 `0.36.1-test`，Android versionCode 57。基于 0.36.0 测试版继续修改，没有发布或安装到手机。

## 行为

- “随手、启蒙、新手、基础练习”仍由本地轻量选棋器落子。强引擎的分析结果只用于提示，不进入电脑的落子通道；请求和回调两端均拒绝把 USI 落子交给这四档。
- 原六档保留原搜索预算。检查发现它们与即时分析共用进程，深度分析留下的搜索状态可能影响限深选棋；现在切回电脑落子时先发 `isready`，等待 `readyok` 清理完成再发送对弈请求。所捆绑 YaneuraOu 的 `isready()` 会重建搜索线程、清理置换表和搜索历史。连续分析阶段仍复用缓存，线程与内存设置保持原值。
- 人机对弈及其复盘、试下只显示玩家执棋方起手的候选线路，支持玩家先手或后手。电脑回合清除候选及箭头，轮到玩家后恢复；保存的试下记录保留玩家座位。候选线路里的对手应手仍保留，播放时可查看完整变化。
- 未分配玩家座位的导入棋谱和本地双人棋谱仍可分析双方。整局报告的评分和分类仍覆盖全局，人机棋谱的候选线路按玩家座位筛选。
- 暂停即时分析不再增加对弈版本号或丢弃电脑已选的着手。在电脑回合点击继续深入，会等到玩家回合再分析。

## 验证

检查真实 YaneuraOu 协议顺序：分析结束或取消 → `isready` → `readyok` → 原档位的 `go`，并验证重置期间取消和替换请求可以恢复。最低旧档仍发送 `go movetime 250 nodes 80 depth 1`。分析回调不会提交为落子。

交互测试覆盖双方座位、旧结果拒绝、己方线路完整播放、电脑回合清空、暂停保留电脑着手、复盘、试下及存档后座位恢复。四档弱电脑在开启分析时分别轮换双方实际落子，均返回合法着手且未发出强引擎对弈请求。固定种子及浅搜索战术回归继续通过。

验证数量、包大小及 SHA-256 见 [验证摘要](releases/v0.36.1-test-validation.json)。原始记录保存在 `review/app/own-side/`，截图及交互记录在 `review/app/experience36/`。同时复跑了变化界面、可选保存、继续对局和实时回放回归。

Android ARM64 调试 APK 和 Windows x64 测试 ZIP 在 `builds/`。Windows 成品运行检查与 APK 内容校验分别进行。ADB 检测到一台设备，但状态为 `unauthorized`，本次没有进行安卓实机触摸或性能验证。
