# 中将棋规则与数据格式

规则标识：`chu-renmei-2019-digital-1`。依据[日本中将棋连盟 2019 规则](https://www.chushogi-renmei.com/kouza/rule2007.htm)、[补充解释](https://www.chushogi-renmei.com/kouza/rule_hosoku2004.htm)和[棋子走法图](https://www.chushogi-renmei.com/kouza/koma.htm)。同机、TCP 和蓝牙统一采用通信对局的香车末段升变补充。程序在提交前阻止非法着手，不执行实体比赛的触子处罚。

## 对弈

12×12 棋盘，双方各 46 枚棋子。吃子丢弃，不产生持驹。首次进入敌方四段、阵内吃子或从阵内吃子退出时可升变；未升变的步兵与香车另有末段机会。允许死子。原始棋种与升变位分开保存，不允许二次升变。

狮子、角鹰、飞鹫的双步作为一手确认。可直接跳跃，或选择经过格以吃两子、居食或往返。往返需可经过的空格。狮子的足按整手开始时局面判断，并移除攻击狮子的起点以处理影足。先狮子的受保护狮子免于下一手被吃；付食优先于先狮子。步兵和仲人不算付食，成步兵、成仲人按升变后棋种判断。

玉将和太子均被吃才结束；判定将死时，检查对方能否在一手吃掉所有剩余王族，以及本方是否存在脱困或先吃掉敌王族的应手。中将棋不禁止暴露己王。残局胜利排除未升变步兵、仲人和死子，并保留立即回吃机会；双方可以确认和棋。

重复局面不自动和棋。连续王手者优先承担变着责任，其次是单方面攻击敌子的棋手，否则是重复局面出现时的行棋方。第三次重现后，责任方不能继续导向同一后继局面。双方连续往返时，先往返者必须变着。不同经过格返回同一局面不能规避此限制。

## 操作与存储

菜单 → 开始对弈 → 中将棋。支持同机双人、摆局、JSON 导入导出、棋谱库、回放、从回放位置继续、IP 和安卓蓝牙。没有中将棋引擎、评分、报告或电脑对手；进入时停止本将棋引擎与分析任务。双指缩放 1–3 倍并平移，复位恢复全盘。长按棋子显示全名与走法。多段路径须确认；取消、转屏或退后台清除预览，确认前计时继续。

棋谱包含 `variant: "chu"`、固定 `rules_id`、初始局面和完整着手。着手字段为 `from`、`path`（一或两个落点）和 `promote`。格号按左上角起、逐行编号 0–143；正数为先手，负数为后手。棋子编号见 `chu_catalog.gd`，原始棋种加 32 表示已升变。局面含下一手行棋方与先狮子保护状态，恢复时逐手重建历史。

本将棋当前对局保存在原位置，中将棋使用 `chu-active-game.json`；联机恢复另用 `chu-network-game.json`。公共棋谱库标明棋种。缺少 `variant` 的旧棋谱仍为本将棋。备份版本 2 可读取版本 1，所有棋谱通过校验后才开始恢复；当前对局恢复为棋谱库记录，保留正在进行的对局。

中将棋不导出 KIF、CSA、USI 或 SFEN。导入这些格式仍按本将棋解析。

## 联机

独立协议版本 2，默认 TCP 端口 9232。握手核对棋种、规则与房间码；重连还需会话令牌。房主验证完整着手，客人等待确认再提交。单调序号防止悔棋后的旧消息再次生效；局面校验摘要包含完整历史。

快照分块，每块原始数据最多 12,000 字节，经 Base64 编码；保持传输层 64 KiB 单消息限制。最多 2 MiB 棋谱、10,000 手。全部分块及摘要、每步合法性校验成功后才替换局面。同步或断线期间暂停计时。悔棋、和棋、再战须双方确认，再战互换先后手。

蓝牙复用安全 RFCOMM 传输层。自动化测试覆盖适配器中的实际 JSON 编解码、整手确认、悔棋、和棋、再战及版本拒绝；**尚未完成双手机蓝牙实测**。

## 验证入口

- `godot/tests/chu_rules_test.gd`：棋种、方向、阻挡、升变、狮子补充示例、王族、残局与重复责任。
- `godot/tests/chu_storage_test.gd`：两种棋谱、旧记录、备份 v1/v2、损坏记录拒绝。
- `godot/tests/chu_network_test.gd`：真实本地 TCP、1,600 手分块、过期消息、重连与原子替换。
- `godot/tests/chu_bluetooth_test.gd`：蓝牙适配器自动化，不代替双手机测试。
- `--chu-probe`：窗口、手势、回放、引擎隔离与虚拟棋路。
- `--chu-peer --peer-config=...`：隔离真实对局存档的两设备局域网测试。Android 仅调试包读取私有目录测试请求，发行包不接受该请求。
