# 整局报告：0.12 的算法与参考边界

0.12 增加按同一横轴排列的开局、中局、终局评分条、双方准确率、可点击的阶段明细，以及可选的平均评价损失（ACPL）。图表使用先手／后手明暗面积、中央零线和阶段分界。停止／继续保留实际引擎结果；未分析区间不会产生评分。导出 JSON 包含逐手输入、阶段、双方统计和模型版本 `shogi-report-12-estimate`。

这些是引擎分析估计。它们没有经过将棋棋手等级分数据校准，也不生成 Elo。国际象棋参考应用的规则、评分尺度与将棋不同，不能宣称所有数字都与原版一致。

## 评分尺度与准确率

界面胜率继续使用 [既有将棋换算说明](COACHING.md) 中的 `100 / (1 + exp(-score / 600))`。参考应用使用 `100 / (1 + exp(-cp × 0.00368208))`。报告按两者的斜率比 `600 × 0.00368208 = 2.209248` 转换单位，再使用参考模型的 ±1000 限幅。这是明确的尺度迁移，不是经验拟合出的将棋准确率模型。

单手准确率：

```
wpl = max(0, before_chance - after_chance)
accuracy = clamp(103.1668 × exp(-0.04354 × wpl) - 3.1669, 0, 100)
```

胜率没有下降或实际着手与引擎首选一致时，记 100，损失记 0。修复了旧版将任意损失 ≤20 的着手直接称为“最佳”的问题。原始评分变化仍保存在 samples 和 observed_loss，便于解释不同局面搜索深度带来的变化。

多个有效着手的聚合采用参考式：

```
-1.668449 × mean(wpl)
-5.38865 × ln(mean(normalized_cpl) + 10)
+0.672122 × mean(move_accuracy)
+48.1131
```

整体准确率另扣不精确、失误、漏着的递增惩罚，上限 6；阶段分数不扣该项。因此整体分数不等于各阶段分数的简单平均。界面 ACPL 已转换回将棋引擎评分单位。

只有九条内置开局示例实际匹配的共同前缀、唯一合法着不参与准确率。它们仍保留在着手计数中；没有有效样本显示 `—`，不会伪造 100。当前尚未迁移原版连续将军循环等复杂权重规则。

## 将棋阶段划分

阶段单调前进，覆盖每一手，允许短棋谱只有一个阶段，不按总手数平均分成三份。

- 平手从开局开始；第 16 手以后，已有两次吃子或达到展开活动阈值时转为中局；最迟在第 40 手转入中局。
- 自定义 SFEN 从中局开始，不假定它是标准开局。
- 王周围两格内出现至少两枚对方攻子、其中有成子且接近程度达到阈值时转入终局；引擎报告詰み线路也触发终局。
- 不根据盘上总子力减少判断终局。被吃的棋子仍可能作为持驹打入。

这是保守的启发式分段，不能替代人工判断。局面与每手分析结果保留在报告中；明细显示触发原因。
