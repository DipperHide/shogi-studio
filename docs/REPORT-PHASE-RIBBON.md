# 阶段报告条：参考与将棋适配

0.21 根据用户提供的 Chessis 20.9 APK 静态布局和控制代码调整主报告的阶段条。阶段详情弹窗、准确率详情和主报告阶段条是三个独立视图。

## 参考依据

- `res/layout/phase_ribbon.xml`：顶部 6／1／5 dp 的分隔区、22 dp 阶段标题、两侧 12 dp 内缩、34 dp 评分条、两位棋手之间 20 dp 间隔。
- 同一布局中的棋手行：22 dp 先后手标记、仅胜者显示的 16 dp 奖杯、12 sp 姓名及最多两行；行顶间隔 6 dp，左右内边距 10 dp。
- 摘要使用居中且允许换行的 Flexbox；准确率为 14 sp，ACPL 和估计等级分为 12 sp。胶囊保留各自的文字尺寸、边距及独立点击行为。
- `bg_game_report_phase_side_group.xml` 和 `bg_game_report_phase_summary.xml`：半透明底色、蓝色边框、8／6 dp 圆角。
- `p328r2/C4570h.java` 的 `m9430x`、`m9431y`、`m9432z`：去掉姓名中的装饰符和尾部数字等级分，只加粗胜者；阶段评分取整并加百分号；整体准确率保留最多一位小数。缺失阶段不显示评分，缺失棋手数据不生成该组。没有等级分时保留“—”入口。
- `p304n5/AbstractC4378m.java` 的 `m9014p`：整体数值不足 100 而四舍五入到 100 时，显示 99.9%。标题和评分段共享同一阶段权重。

以上路径相对于本机 `.work/chessis-reference/`。原 APK 与反编译文件未加入源代码仓库；三个新图标的来源散列在 `godot/assets/reference-ui/provenance.json`。参考 APK 依赖缺失的运行分包，未进行原版动态逐屏对照。

## 实现与边界

`shogi_report_phases.gd` 使用原生容器、按钮和自动换行布局，替代固定高度的绘制区域。字号按 Godot 整数像素设置：原 11.5 sp 的阶段分数为 12，9.5 sp 的定式标签为 10。阶段条使用现有已分析着手数据和将棋阶段划分；颜色、百分比与现有报告指标一致。

棋手标记改为将棋「歩」。只有真实定式记录的全定式阶段显示“定式”；唯一合法着等无计分数据的阶段显示“—”。将棋等级分没有经过校准，因此入口解释当前不可用，不产生虚构等级分或段位。

控件支持触摸、键盘焦点及可读的无障碍名称。打开阶段、准确率、ACPL 或等级分说明后返回，保留报告当前选中的手数。布局仅在报告数据改变时重建，调整窗口大小直接触发容器重排。

本轮测试与成品验证见 [0.21 验证记录](TESTING-0.21.md)。布局适配不能证明全应用 UI 或所有算法已完整复刻。
